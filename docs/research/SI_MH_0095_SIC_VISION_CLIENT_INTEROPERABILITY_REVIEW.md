## Intended real use case
Operator authorizes a project and separately connects each GPT/Claude client/account to one RIGHTWARE-controlled SIC service. Each uses its own authorized identity/scope. Example: operator asks GPT to prepare synthetic project requirements and assign implementation to Claude, review to a second GPT. Desired tools create/publish distinct tasks, claim with a lease, read scoped context and decisions, save sourced observations and checkpoints, handoff/accept atomically and submit for review. Another authorized agent can resume from the persisted state without copying the previous chat. Task scheduling is separate from task state: with interactive MCP, a human must start/ask each client unless the host explicitly offers supported triggering; a connector does not launch another vendor's chat. Fully unattended single-command execution needs a separately built orchestrator and supported provider API/CLI/runtime adapters, execution budgets and audit/approval controls. No login cookie scraping, password sharing or bypass of vendor limits. SIC does not merge native chat history, memories, accounts or model weights.

Official vendor docs checked 2026-11-24: OpenAI custom MCP plugins read/write tools and connection URL/tunnel subject to access/permissions (https://developers.openai.com/api/docs/guides/custom-mcp-server); Claude custom remote MCP cloud-side and OAuth connection (https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp); Claude connector availability (https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities). Subscription vs API billing separate, with possible eligible credits/approved integrations (https://help.openai.com/en/articles/9039756-managing-billing-for-chatgpt-and-the-api-platform; https://support.claude.com/en/articles/8977456-how-do-i-pay-for-my-claude-api-usage).
