## Scope and design
Test-only sec_r2_x02.py derives two separate schemas and six separate logins from the C0 schema/seed, in existing marked PostgreSQL disposable job; no reuse of roles between variants, no drop of existing objects. Both add lifecycle/generation and grant epoch, RLS identity+active-state predicate, NOLOGIN at principal R0, bounded explicit session termination by trusted bootstrap, fresh password on regrant, actual signed synthetic generation validation. C1 has no completion/release guarantee. C2 additionally serializes control operations on principal lifecycle row, stores one-time reserved/admitted/emitting/released/cancelled permits, cancels unadmitted permits at R0, blocks R1 until no sessions/outstanding permits, allows previously admitted bounded local release before R1, leaves uncertain outcome EMITTING and denies replay. Local byte sink only, not external delivery. All privileged control operations execute in existing trusted bootstrap fixture; this is deliberately not a least-privilege production broker. Restricted roles cannot alter metadata. Single fixture principal/resource, fixed purpose, no external API or mutation path. Grant-specific revoke tests fresh reads and reserved permits only, no whole-scope R1 for grant revoke or stale grant transactions. R0/R1 apply only to candidate schema/role, not other independent C0 authority. Actual old MVCC transaction observation recorded; NOLOGIN not claimed to terminate sessions. Regrant rotates credential and increments principal generation at revoke. All candidate states disposable; no production policy decision.
